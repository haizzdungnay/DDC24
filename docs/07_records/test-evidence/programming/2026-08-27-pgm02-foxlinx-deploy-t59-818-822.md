## 1. Vì sao lát này phải deploy CẢ backend

`T59-819` là thay đổi **backend**: `stHunks[]`/`fbdChanges[]` do máy chủ tính.
Chỉ đẩy `dist` lên bo sẽ cho một kết quả trông như thành công — giao diện mở
được, khay So sánh hiện ra — nhưng nó sẽ hiện *"máy chủ chưa trả bảng khác biệt
chi tiết"* cho một thiết bị mà ta vừa tuyên bố là đã có tính năng đó.

Đo trước khi deploy backend, đúng như vậy: `grep -c stHunks` trên phản hồi của
bo trả **0**. Fail-closed hoạt động đúng thiết kế, nhưng "đúng thiết kế" ở đây
nghĩa là *chưa deploy xong*.

## 2. Các bước đã chạy

| Bước | Lệnh | Kết quả |
|---|---|---|
| Sao lưu `dist` | `cp -a /opt/mkddc-web/dist dist.bak-t59-818-822-20260827T165530Z` | OK |
| Sao lưu binary | `cp -a mkddc-web mkddc-web.bak-t59-818-822-20260827T165530Z` | OK (14 MB) |
| Build FE phát hành | `VITE_PROGRAMS_WORKSPACE_V2=1 npm run build:release` | chunk `programming` **132,94 KiB** gzip / ngân sách R3 165 KiB |
| Đẩy FE | `tar` + `scp` (bo Buildroot **không có `rsync`**) | 1,1 MB |
| Cross-build BE | `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w"` | ELF aarch64 **statically linked**, 15 MB |
| Đẩy BE + restart | `install -o mkddc -g mkddc -m 0755` + `systemctl restart mkddc-web-pi` | `active` |

**Cờ build-time — bẫy đã tránh được lần này.** `npm run build:release` chỉ đặt
`VITE_PROGRAMMING_REV_A=1`. Workspace PGM-02 còn cần `VITE_PROGRAMS_WORKSPACE_V2=1`,
mặc định **TẮT** theo `DDD-SW-PGM02-WORKSPACE-001 §11`. Bản build đầu tiên trong
phiên này thiếu cờ đó và đã phải build lại — kiểm bằng cách grep route canonical
trong chính bundle sinh ra, không tin vào lệnh đã gõ.

`CGO_ENABLED=0` cho binary tĩnh nên **không dính glibc/GLIBCXX của bo** — đây là
lớp lỗi đã cắn ở các lát C++ trước.

## 3. Kiểm chứng TRÊN BO sau deploy

| Phép kiểm | Lệnh | Kết quả |
|---|---|---|
| Dịch vụ | `systemctl is-active mkddc-web-pi` | `active` |
| Sức khoẻ | `GET /api/v1/health` | `status:ok`; core/io_shm/iobus/mcu_connection/plc_shm/web đều `ok`; **`version 0.1.0-be-b6c`** (binary mới) |
| Core/IObus | `systemctl is-active mkddc-core mkddc-iobus` | `active`, `active` |
| Bundle mới | `GET /` | `assets/index-B9rT6_gb.js` — khớp bản vừa build |
| Chunk Programming | `GET /assets/programming-DzUEU_Ka.js` | `200`, `535 502` byte |
| SPA fallback | `GET /eng/programming/programs` | `200` |
| Đăng nhập | `POST /api/v1/auth/login` (`admin`) | OK |
| Danh sách Project | `GET /api/v1/programming/projects` | OK, có Project thật |
| **`T59-819` typed diff** | `GET .../changes/{to}` | **có đủ `stHunks`/`fbdChanges`/`truncated`/`nextCursor`**; `stHunks[0]` mang `changeType:"ADDED"`, `afterLineCount:4` — số THẬT từ Revision trên bo |
| **Fail-closed cursor** | `?cursor=rac` / `?cursor=-1` / `?cursor=0` | **400 / 400 / 200** |

Phép kiểm cuối đáng chú ý: `cursor` rác bị **từ chối** chứ không âm thầm coi là
0. Đọc lại từ đầu khi client tưởng mình đang đọc trang hai là cách một danh sách
trông đầy đủ trong khi thiếu mất phần giữa.

## 4. Đường lùi

| Thành phần | Bản lùi |
|---|---|
| FE | `/opt/mkddc-web/dist.bak-t59-818-822-20260827T165530Z` |
| BE | `/opt/mkddc-web/mkddc-web.bak-t59-818-822-20260827T165530Z` |

Lùi: `mv` thư mục `dist`, `install` lại binary cũ, `systemctl restart
mkddc-web-pi.service`. Hai bản lùi phải đi **cùng nhau**: binary cũ với `dist`
mới sẽ cho khay So sánh hiện "máy chủ chưa biết so" trên một hệ đang chạy tốt.
