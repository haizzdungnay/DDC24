# WEB-HIST-002 SQLite Historian Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build crash-safe SQLite hot/archive storage, rehearsal migration, and recovery primitives without activating the new writer or changing legacy historian behavior.

**Architecture:** Open a separate `historian-v2.sqlite` with one FULL-sync WAL writer connection. Mirror committed `historian.conf` revisions immutably, store generation-aware 15-second hot aggregates and explicit gaps, write one deterministic stdlib archive codec, and migrate only from completed native SQLite backups using a frozen manifest. Legacy `trend.sqlite`, `TrendStore`, `Sampler`, VP diagnostic sampler, `/history`, and frontend remain authoritative and unchanged.

**Tech Stack:** Go 1.26, `database/sql`, existing `modernc.org/sqlite v1.29.10`, Go standard library (`crypto/sha256`, `encoding/binary`, `encoding/json`, `os`, `io`).

---

## Scope Locks

- New store path must differ from legacy `TrendDBPath`.
- No scheduler goroutine, coherent-snapshot sampling, shadow write, query cutover, frontend edit, legacy quiesce, or legacy table/file deletion.
- `historian.conf` stays policy authority. SQLite policy rows are immutable mirrors only.
- Native backup page stepping is cancellable but not restart-resumable. Interrupted backup restarts into a new partial destination.
- Migration row-copy checkpointing begins only after a completed immutable backup passes integrity and checksum verification.
- Collision resolution runs before 15-second aggregation.
- No `prepared` policy activation or config commit-point changes in this slice. Those require coordinated cutover after WEB-HIST-003 readiness.
- Policy mirror is best-effort eventual-current: v2 failure must never fail or roll back WEB-HIST-001 policy commit. Restart mirrors the current exact committed revision; missing superseded revisions are allowed and no durable outbox is added.
- Add a `ponytail:` comment where conservative capacity projection remains pending measured codec/eMMC evidence.
